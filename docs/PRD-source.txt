PRD dan Skema Prompt — Marketplace Multi-Toko COD




  PRD dan Skema Prompt — Marketplace
  Multi-Toko COD
    Nov 6, 2026       ·   ​@Fahmi

  Dokumen ini memuat PRD marketplace multi-toko dengan pembayaran tunai (COD) dan
  13 prompt berurutan untuk membangunnya: frontend Next.js dan backend Express +
  MySQL di folder terpisah.


  Ringkasan
  Produk ini adalah marketplace multi-toko: pemilik toko mendaftar, diverifikasi Super
  Admin, lalu menjual barang yang dibayar tunai (COD) saat bertemu pembeli.

         Pengguna: Super Admin (mengelola platform), Admin Toko (penjual sekaligus kasir),
         Customer (pembeli).
         Pembayaran: hanya tunai (COD). Pembeli dan penjual menyepakati lokasi dan waktu
         lewat chat, lalu Admin Toko menekan "Konfirmasi lunas" setelah uang diterima. Tidak
         ada ongkir atau kurir karena transaksinya bertemu langsung.
         Tampilan: beranda mengikuti tata letak gambar referensi, diisi data nyata dari
         database. Logo dan merek pada gambar referensi tidak dipakai; nama produk di
         dokumen ini memakai placeholder NamaMarketplace .
         Teknologi: JavaScript penuh. Frontend Next.js (App Router) dan Tailwind CSS;
         backend Express dengan Socket.IO untuk chat; database MySQL yang bisa diimpor
         lewat phpMyAdmin.
         Struktur: tiga folder terpisah, frontend/ , backend/ , dan database/ .


  Asumsi yang saya ambil
         Stok berkurang saat Admin Toko menekan Konfirmasi lunas, sesuai catatan Anda.
         Sejak checkout, jumlah itu ditahan sebagai stok dipesan supaya tidak terjual dua kali.
         Satu pesanan hanya berisi barang dari satu toko. Keranjang berisi banyak toko
         dipecah menjadi beberapa pesanan saat checkout.
         Toko dianggap tidak aktif jika tidak ada login dan tidak ada pesanan selama 30 hari.
         Super Admin bisa mengubah angka ini.
         Hanya Rupiah, bahasa Indonesia, dan zona waktu WIB.

  Alur pengguna
  Setiap pesanan berjalan melalui empat status, dan stok serta pemasukan toko baru
  berubah saat Admin Toko menekan Konfirmasi lunas.




  alur status pesanan COD · 4 status, 1 cabang batal

  tokonya (SA2). Pesanan hanya bisa dibatalkan sebelum lunas, dan stok yang ditahan
  dikembalikan.

         Lapisan backend: route memanggil controller, controller memanggil service, service
         menjalankan SQL. Transaksi database (checkout, konfirmasi lunas, penyesuaian stok)
         hanya ada di service.
         Variabel lingkungan backend: PORT , DB_HOST , DB_USER , DB_PASSWORD , DB_NAME ,
          JWT_SECRET , CLIENT_ORIGIN , UPLOAD_DIR , SMTP_* (opsional).
         Variabel lingkungan frontend: NEXT_PUBLIC_API_URL , NEXT_PUBLIC_SOCKET_URL .
         Pilihan Next.js: halaman produk dan toko diuntungkan render di server untuk SEO.
         Jika Anda lebih suka React + Vite, ganti satu baris di Prompt 0.

  Keamanan dan non-fungsional
  Aturan paling penting adalah isolasi data antar toko: store_id selalu diambil dari akun
  yang login di server, tidak pernah dari input klien.


  Keamanan
         Sandi: bcrypt dengan cost 12, minimal 8 karakter.
         Sesi: JWT di cookie httpOnly, Secure di produksi, SameSite=Lax , berlaku 7 hari;
         logout menghapus cookie.
         Otorisasi: middleware authenticate , lalu authorize(role) , lalu storeScope untuk
         rute Admin Toko.
         Validasi: semua input divalidasi dengan zod di backend; SQL memakai placeholder,
         tidak pernah menggabung string.
         Perlindungan HTTP: helmet, CORS hanya untuk CLIENT_ORIGIN , rate limit ketat pada
         login, daftar, dan lupa sandi, lebih longgar pada API lain.
         Upload: hanya jpg, png, webp, maksimal 2 MB, nama file diacak, tipe dicek dari isi file,
         ukuran diperkecil dengan sharp.
         Pesan error: login gagal selalu memakai pesan yang sama; detail teknis hanya ke log
         server.
         Rahasia: disimpan di .env , tidak masuk Git; .env.example disediakan.

     3. Admin Toko: /api/store/orders (daftar dengan filter status dan paginasi,
